# ♠ QWX POKER — подпольный покер-клуб в 3D (браузер)

Texas Hold'em на 6 мест: лакированный стол, латунные таблички-кнопки в борту, руки от первого лица,
дым сигареты, виски со льдом, музыка «с пластинки». Играешь с друзьями по ссылке или с ботами.

## Запуск

```bash
npm install
npm run build      # собрать сайт в dist/
npm test           # тесты движка
npm start          # сервер: сайт + столы по WebSocket (порт 3000)
```

Открыть `http://localhost:3000`. Без сервера (`?offline` или чистый статический хостинг) — тренировочный стол с ботами.

## Публикация

Мультиплееру нужен Node-сервер (WebSocket). Два варианта:

1. **Всё на одном сервере** (VPS, Render, Railway, Fly.io): `npm run build && npm start`, переменная `PUBLIC_URL=https://твой-сайт`.
2. **Сайт на GitHub Pages + сервер отдельно**: собрать с адресом сервера
   `VITE_SERVER_URL=https://poker-api.example.com npm run build`, папку `dist/` залить на Pages,
   а сервер (`npm start`) запустить на Render/Railway.

## Вход: Telegram и Google

### Telegram
1. Создайте бота у [@BotFather](https://t.me/BotFather) → получите токен.
2. Там же: `/setdomain` → домен сайта с игрой (виджет входа работает только на нём).
3. В `.env`: `TELEGRAM_BOT_TOKEN=...` и `TELEGRAM_BOT_NAME=имя_бота` (без @).

На экране входа игрок нажимает «Log in with Telegram», подтверждает вход в Telegram — и сразу попадает в клуб.
Сервер проверяет подпись данных токеном бота.

### Google

1. [Google Cloud Console](https://console.cloud.google.com/) → APIs & Services → Credentials → **Create credentials → OAuth client ID** → тип **Web application**.
2. В **Authorized JavaScript origins** добавьте адрес сайта с игрой (и `http://localhost:3000` для проверки дома).
3. Скопируйте Client ID в `.env` → `GOOGLE_CLIENT_ID=...` и перезапустите сервер.

После этого играть можно только с аккаунтом Google: сервер проверяет подпись токена Google и выдаёт свою сессию на 30 дней.
Без `GOOGLE_CLIENT_ID` сервер работает в режиме разработки (вход по токену браузера).
Тренировочный офлайн-стол (`?offline`) — только для проверки графики, он не сохраняет ничего на сервере.

## Звук

Музыки в игре нет — только процедурные звуки стола: фишки, раздача, переворот карт, стук по сукну, нажатие кнопок.

## Бутик

В витрине: смартфон Pro Max (бордо), ТТ, ключ от «кубика». На столе одновременно — до двух вещей
(третья вытесняет самую давнюю). Вещи видят все игроки: у тебя — у рук и стакана, у соперников — у их рук.
Модели процедурные, без логотипов и торговых марок — названия меняются одной строкой в `src/shared/Catalog.ts`.

Новый предмет добавляется в двух местах:
- `src/shared/Catalog.ts` → `CATALOG` (id, название, цена, ключ модели);
- `src/client/scene/items.ts` → `ITEM_MODELS` (3D-модель).
Купленное лежит на столе у владельца — его видят все игроки.

## Устройство

```
src/shared/   движок: колода, оценка рук, стол с сайд-потами, боты, хост стола
src/server/   HTTP + WebSocket, вход по токену браузера, экономика, ладдер
src/client/   Three.js-сцена, лобби, интерфейс, звук
```

Производительность: тени пересчитываются только при движении, фишки — один InstancedMesh,
FPS-монитор держит частоту экрана (60/90/120): сначала отключает кино-эффекты, потом снижает чёткость.

## Руки от первого лица

Модель кисти (скан с текстурами кожи) — `public/models/`: `hands.bin` (сетка, скелет, веса), `hand_*.jpg` (цвет, рельеф, шероховатость).
Скелет и привязка кожи сделаны скриптами в `tools/`:
```bash
python3 tools/hand_parse.py исходник.obj   # разбор OBJ
python3 tools/hand_split.py                 # левая и правая кисть, склейка вершин
python3 tools/hand_rig.py public/models/hands.bin   # пальцы, суставы, веса
```
**Лицензия модели:** RigModels — бесплатно только для личного использования. Для коммерческого запуска нужна их Premium-подписка.
